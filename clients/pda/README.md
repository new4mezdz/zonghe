# 仓库 PDA 扫码 1.1

东集 CRUISE2 / Android 11 的原生 Android 客户端，与综合服务的[仓储扫码模块](../../service/modules/pda_report/README.md)配套使用。源码从原 `D:\9090\pda\android` 纳入本仓库，后续在本目录维护。当前版本为 `1.1.0`，版本号 `2`，包名仍为 `com.warehouse.pda`。

## 扫码流程

1. 首页选择“返回调换”或“调换入库”，进入独立扫码页面。
2. 按实体扫码键，条码先保存到本批列表，每条可查看完整码或删除。
3. 同批码值去掉首尾空白后去重，保留大小写和前导零；删除后可重扫。
4. 核对后点“上传本批”。提交后锁定该批，不再允许新增或删除；全部记录确认后开启下一批，下一批可再次扫同一码。

两种业务和不同服务地址分别保留批次。草稿不会自动上传；已提交批次断网时保留本机，应用在前台联网时自动补传。首页、设置、详情及应用后台暂停收码。

上传仍使用原 `POST /api/scans` 协议：“返回调换”对应 `operation=return`，“调换入库”对应 `operation=inbound`，`source=pda`。批次编号只用于本地管理，不加入请求正文。每批逐条上传，可能部分成功；重试复用原 UUID，不重发已经确认的记录。

## 安装与现场设置

用原签名构建后直接覆盖安装，**不要卸载旧版或清除应用数据**。数据库升级保留旧版历史、待传记录及原 UUID，不追溯合并旧版同码记录。

PDA 连接现场 Wi-Fi，在“服务与扫码设置”里填写综合服务根地址，默认 `http://10.164.62.212:5000`，不要附加页面或 API 路径。密钥是可选项，服务未启用时留空。

打开设备自带“扫描工具”并保持后台运行，在本应用点击“一键配置东集扫码”并保存。若固件未响应，手动配置广播输出，Action 为 `com.warehouse.pda.SCAN`，字段名为 `scannerdata`。配置后实际扫一个码确认。

备用键盘输出模式必须配置 Enter、Tab 或 CR/LF 结束符。界面不再提供原大输入区；未完成或保存失败的片段会保留并显示处理入口，不自动拼入下一码。

更改服务地址不会转移已经提交的批次。未提交草稿只能整批迁移，不能与目标已有批次合并；旧地址的批次可在“未完成批次”中查看和切回处理。

## 构建

```powershell
cd clients\pda
.\build-android.ps1 -JdkRoot D:\jdk8
```

首次没有 SDK 时可加 `-InstallToolchain`。使用 Android API 30、build-tools 30.0.3，最低 Android 8.0（API 26）。SDK 默认存放在 `%LOCALAPPDATA%\WarehousePda\toolchain`，构建中间文件在 `%TEMP%\warehouse-pda-android`，可通过 `-SdkRoot`、`-BuildRoot` 指向其他仓库外目录。

交付文件为本目录 `release\仓库PDA扫码.apk`，不提交到 Git。默认沿用 `%LOCALAPPDATA%\WarehousePda\signing\warehouse-pda-test.jks` 中的本机签名；该密钥不在仓库内。在其他电脑覆盖更新已有应用，需要安全提供同一签名密钥，通过 `-KeyStore`、`-KeyAlias` 及脚本支持的密码环境变量构建，不能用新生成的签名覆盖旧应用。

测试脚本、测试数据库、截图、结果与依赖缓存必须放在仓库之外。不要直接启动完整综合服务进行客户端测试，以免触及其他现场设备；使用本机测试服务。实体扫码广播和现场网络仍需在 PDA 上验证。
