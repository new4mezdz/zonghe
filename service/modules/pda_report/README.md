# 仓储扫码报表

综合服务首页的“仓储扫码报表”入口位于 `/pda_report/`。综合服务直接通过 TCP 连接现场读码器、自动收码，同时接收东集 PDA 上传的扫码记录，无需运行原 Windows 采集 EXE。页面展示码值、北京时间、设备编号、入库/返回、来源，支持筛选、分页、汇总、每日趋势和 CSV 导出。报表每 10 秒自动刷新，读码器状态每 4 秒刷新（仅页面可见时）；新采集记录保存后也会触发报表刷新。

配套 Android 客户端源码、扫码流程与打包说明见 [clients/pda](../../../clients/pda/README.md)。

## 部署与 PDA 配置

1. 在运行综合服务的机器上更新代码，按原方式启动或重启 `service/app.py`。模块随综合服务一起监听原端口（默认 5000），无需另开扫码进程。同一地址和端口不要同时运行独立的“扫码统一服务.exe”。
2. 可在 `service/.env` 中配置以下项目，也可设置同名环境变量。配置优先级为 Flask 配置、进程环境变量、`service/.env`、默认值。

   ```dotenv
   WAREHOUSE_API_KEY=
   WAREHOUSE_SCAN_DATA_DIR=D:\ServiceData\WarehouseScan
   ```

   `WAREHOUSE_API_KEY` 是可选共享密钥，最多 256 位无空格 ASCII 字符；启用后 PDA 和报表填写同一密钥，页面上的读码器控制也受此密钥保护。读码器本身通过 TCP 发码，无需填写 HTTP 密钥。留空仅适合受控内网。配置示例见 `service/.env.example`，修改后重启综合服务。
3. 将现有 `仓库PDA扫码.apk` 安装到东集 PDA，连接能够访问综合服务的现场 Wi-Fi。服务地址填写服务器根地址，例如 `http://10.164.62.212:5000`，不要添加 `/pda_report/` 或 `/api/scans`。服务器需允许现场网段访问该端口。
4. 打开设备自带“扫描工具”并保持后台运行；在 APK 的“服务与扫码设置”中点击“一键配置东集扫码”，保存服务地址及密钥，再点击“测试连接”。如固件不响应一键配置，在设备扫描工具中选择广播输出，Action 为 `com.warehouse.pda.SCAN`，字段名为 `scannerdata`。
5. PDA 1.1 从首页选择“调换入库”或“返回调换”，按实体扫码键，检查本批列表并删除错码，再点击“上传本批”。同一批内排除重复码，全部上传确认后开启下一批。PDA 显示“已上传”后，报表应在下一次刷新时出现记录。

APK 上传协议保持不变，旧版仍可接入；新版 PDA 1.1 需覆盖安装新的 `仓库PDA扫码.apk`，不能卸载后重装。设备先保存到本机，未提交草稿不会上传，提交后断网时保留待传记录；重新联网并打开应用后补传。每批通过现有接口逐条上传，可能部分成功，重试复用事件编号。当前应用没有退出后持续补传的后台服务。存在未提交或待传记录时不要卸载应用或清除其数据。

## 读码器直接采集

1. 停止原“入库自动扫码.exe”，避免占用读码器连接或重复上报。读码器应启用 TCP 服务端输出，综合服务作为客户端主动连接；服务所在机器必须能够访问读码器的 IP 和端口，手机能访问报表并不代表服务器能访问读码器。
2. 打开“仓储扫码报表”中的读码器连接设置，填写实际 IP、端口并保存。默认 IP 为 `192.168.30.180`、端口 `51236`，只是原项目默认值，应以现场参数为准。
3. 选择与设备一致的字符编码和分帧方式。支持 UTF-8、GBK、ASCII；自动模式兼容换行、STX/ETX，并在空闲间隔后将无结束符内容作为一码。设备能设置结束符时建议使用 CR/LF 换行模式；固定长度模式按字节数分帧。自动模式的空闲间隔需大于一码内的传输间隔、小于两次扫码间隔。
4. 点击“连接采集”，确认状态为“已连接”，扫一个码并检查“已保存”及下方明细。每个完整有效码保存为“读码器 / 入库”，设备编号由连接地址生成；PDA 仍可上传“入库 / 返回”。默认不去重，同一码再次扫码会再次计数；如需过滤设备短时间重复发码，可设置去重窗口。
5. 首次安装默认停止。点击连接后保存启用状态，之后综合服务重启会自动连接；关闭报表浏览器不影响收码。点击“停止采集”会保存停用状态，后续重启保持停止。修改连接参数前先停止采集。

网络断开后按重连间隔持续尝试，页面展示连接状态、最近码值、收码和保存数量及错误信息。面板计数从本次点击启动采集开始，断线重连不清零，停止后重新启动会清零；历史总量以下方报表为准。只有数据库确认写入成功才增加“已保存”；暂时写入失败会暂停继续接收并重试该事件。待保存事件暂存在内存，停止时仍未保存的记录会明确提示需人工核对；进程被强杀或断电时不能保证恢复。服务关闭或故障期间未接收到的码无法自动补采，是否保留并补发由读码器自身能力决定。

同一数据目录只允许一个采集进程持有读码器。部署采用单个综合服务进程；多进程启动时，其他进程会显示占用错误，不能把它们作为具有一致采集状态的负载均衡服务。默认参数与配置文件损坏等错误不会阻止其他综合服务模块启动。

## 数据目录与历史数据

数据库文件为 `scan-events.sqlite3`，读码器设置为同目录的 `reader-settings.json`，采集进程锁文件也位于该目录。未配置目录时，Windows 使用 `%LOCALAPPDATA%\WarehouseScanService`，Linux 使用 `~/.local/share/warehouse-scan-service`，与原独立扫码服务的默认位置相同。扫码数据库默认放在项目外，正式部署建议指定稳定的项目外绝对路径。读码器设置由页面保存，不在项目目录生成配置。

如此前运行过独立扫码服务，先停止该服务，再将 `WAREHOUSE_SCAN_DATA_DIR` 指向原数据目录。更换数据目录或运行账号时，需要停服后复制完整原数据目录，包括仍存在的 SQLite WAL 文件，再启动综合服务。已确认上传的记录不会由 PDA 自动重传到新数据库。备份也应先停服，再复制整个目录。

## 兼容接口与统计口径

| 接口 | 用途 |
| --- | --- |
| `GET /api/health` | PDA 连接检查，返回 `service=warehouse-scan`、`api_version=1` 和 `auth_required` |
| `GET /api/reader/status` | 读码器连接设置、运行状态、最近扫码与采集计数 |
| `POST /api/reader/config` | 停止时保存连接参数（不接受 `enabled`） |
| `POST /api/reader/start` | 连接并保存启用状态，请求正文 `{}` |
| `POST /api/reader/stop` | 停止并保存停用状态，请求正文 `{}` |
| `POST /api/scans` | 保存扫码事件；首次返回 201，相同事件重试返回 200 |
| `GET /api/report` | 筛选、分页、汇总及每日趋势 |
| `GET /api/export.csv` | 导出当前筛选范围，UTF-8 BOM 编码 |

除健康检查外，启用密钥后上述 API 均要求 `X-API-Key`。上传 JSON 保留 `event_id`、`barcode`、`source`（`pda`/`reader`）、`operation`（`inbound`/`return`）、`scanned_at`（含时区）和 `device_id`，可选 `reader_host`、`reader_port`。单次请求正文不超过 2 MiB。服务确认包含 `ok`、原 `event_id`、正整数 `id` 及布尔值 `duplicate`。

读码器控制接口只接受 `application/json`，正文最大 16 KiB。连接参数为 `host`（数字 IP）、`port`、`framing`（`auto` / `line` / `stx_etx` / `fixed`）、`encoding`、`idle_ms`、`fixed_length`、`reconnect_seconds`、`dedupe_seconds`；支持仅提交要修改的字段。正在采集时修改参数或已有其他进程采集返回 409，参数错误返回 400，配置无法保存返回 503。

筛选参数为 `keyword`、`start_date`、`end_date`、`source`、`operation`；分页使用 `page` 和 `page_size`（1–200）。日期首尾均包含，按北京时间统计，趋势展示最近 31 个有记录日期。CSV 单次最多 100000 条，码值内容总量最多 32 MiB，超限时缩小筛选范围。

每次实际扫码生成一个 UUID，网络重试复用同一个 UUID，不重复计数；同 UUID 内容不同返回 409。同一码重新扫描是新事件，会再次计数。返回记录单独统计，不冲减入库次数，不计算实时库存。

## 验证约定

测试脚本、临时数据库、缓存、截图和结果均放在项目目录之外。接口验证可用独立 Flask 应用注册 `pda_report_bp`，通过 Flask 配置 `WAREHOUSE_SCAN_DATA_DIR` 指向外部临时目录；无需启动包含其他现场设备连接的完整综合服务。导入模块或注册蓝图不会连接读码器，正式入口调用 `start_reader_service(app)` 恢复保存的启用状态。自动收码测试使用本机 TCP 模拟器；正式使用前需以真实读码器验证输出协议、网络可达性，并以真实 PDA 验证扫码广播和上传结果。
